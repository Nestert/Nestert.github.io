# Портфолио Екатерины Романовой

Статический сайт-портфолио на Eleventy и Sass. Контент редактируется через Pages CMS, хранится в GitHub и публикуется в Yandex Object Storage.

## Основные адреса

- Основной сайт: <https://omanovar.ru/>
- Технический адрес Yandex Object Storage: <http://omanovar.ru.website.yandexcloud.net/>
- Редактор контента: <https://app.pagescms.org/>
- Репозиторий: <https://github.com/Nestert/Nestert.github.io>
- Бакет Yandex Object Storage: `omanovar.ru`
- Тестовая версия Sites: <https://ekaterina-romanova-portfolio.valenbelousov2344385.chatgpt.site/>

Страница `/admin/` содержит ссылки на Pages CMS и визуальный редактор миниатюр.

## Как устроено обновление сайта

```text
Pages CMS → GitHub (main) → GitHub Actions → Yandex Object Storage → omanovar.ru
```

Pages CMS сохраняет изменения в ветку `main` на GitHub. Каждое сохранение автоматически запускает проверку, сборку и публикацию сайта в Yandex Object Storage. Компьютер и Codex можно закрыть: обновление выполняется на GitHub.

Публикация занимает несколько минут. Её состояние можно проверить в [GitHub Actions](https://github.com/Nestert/Nestert.github.io/actions/workflows/deploy-yandex.yml): зелёная отметка означает, что новая версия опубликована и проверена. Если изменения сохраняются несколько раз подряд, текущая публикация завершается, затем запускается последняя ожидающая версия.

## Добавление новой работы через Pages CMS

1. Откройте <https://app.pagescms.org/>.
2. Войдите через GitHub.
3. Выберите репозиторий `Nestert/Nestert.github.io` и ветку `main`.
4. Откройте раздел «Работы».
5. Выберите категорию:
   - «Живопись»;
   - «Графика»;
   - «Проекты»;
   - «Объекты».
6. Создайте новую запись и заполните поля.
7. Загрузите основное изображение и при необходимости выберите дополнительные фотографии.
8. Нажмите «Сохранить».

Основные поля работы:

- `Название` — название работы;
- `Год` — год создания;
- `Размеры` — например, `51 × 49 см`;
- `Материалы` — например, `холст, масло`;
- `Серия работ` — необязательное название серии, например, `Праздник`;
- `Описание` — основной текст на странице работы;
- `Описание на английском` — сохраняется для будущей английской версии;
- `Основное изображение` — обязательное первое изображение работы и обложка по умолчанию;
- `Дополнительные изображения` — необязательная галерея до 20 фотографий в выбранном порядке;
- `Миниатюра` — необязательная отдельная картинка для списка;
- `Положение миниатюры` — важная точка изображения по горизонтали и вертикали: `50 / 50` оставляет центр, `0 / 0` смещает кадр к левому верхнему углу, `100 / 100` — к правому нижнему;
- `Порядок` — резервный приоритет для работ, которые ещё не добавлены в общий список порядка;
- `Дополнительный текст страницы` — необязательный длинный текст в Markdown.

Визуально подобрать точку можно на странице `/admin/thumbnail/`: выберите изображение, нажмите на важное место и перенесите полученные X и Y в Pages CMS. Страница `/admin/` теперь служит общим входом в Pages CMS и редактор миниатюр.

## Быстрое изменение порядка работ

В Pages CMS откройте отдельный раздел «Порядок работ и серий». В нём находятся перетаскиваемые списки:

- общий «Порядок на странице „Проекты“»;
- «Живопись»;
- «Графика»;
- «Объекты».

Перетащите строку работы за маркер слева и один раз сохраните страницу. Открывать каждую работу и менять число больше не требуется. В списке выбора год показывается перед названием; искать работу можно по названию, году или серии.

После создания новой работы добавьте её в нужный список кнопкой «Добавить элемент» и выберите через поиск. Если работа ещё не добавлена, она всё равно показывается в конце категории: сначала учитывается её старое поле `Порядок`, затем год от нового к старому и название.

Чтобы изменить страницу «Проекты», перетаскивайте серии и отдельные проекты в одном общем списке — их можно свободно чередовать. При добавлении строки выберите тип «Серия» и впишите её название либо тип «Отдельный проект» и выберите проект по названию и году. Новая серия или проект, ещё не добавленные в список, всё равно показываются в конце по резервному порядку.

## Серии и проекты

Поле `Серия работ` в живописи, графике и объектах автоматически создаёт проект-серию на странице `/projects/`. Работы при этом продолжают отображаться отдельно в своих исходных категориях.

- Одинаковые названия серий объединяются независимо от регистра и лишних пробелов.
- Работы без серии не создают отдельный проект.
- В карусели серии показываются основные изображения работ, отсортированные сначала по полю `Порядок`, затем от новых к старым при одинаковом порядке.
- Дополнительные изображения остаются на отдельных страницах работ.
- Проекты, созданные вручную в разделе CMS «Проекты», отображаются рядом с автоматическими сериями.

Для ручного выбора обложки откройте в Pages CMS раздел «Обложки серий» и добавьте название серии и изображение. Название должно совпадать с полем `Серия работ`. Там же можно настроить положение обложки. Если ручная обложка не задана, используется миниатюра или основное изображение самой новой работы серии вместе с настроенной для неё точкой фокуса.

В этом же разделе поле `Порядок` служит резервной сортировкой для новых серий, которые ещё не добавлены в общий список «Порядок работ и серий»: чем меньше число, тем раньше такая серия показывается среди остальных новых серий. При одинаковом порядке сначала идёт более новая серия. Если порядок не указан, используется `0`.

В списках живописи, графики и объектов каждая серия начинается с новой строки и отделяется увеличенным пустым отступом без дополнительного заголовка. Работы одной серии автоматически собираются в цельный блок, даже если в быстром списке порядка между ними находятся другие работы. Все работы без серии также выводятся одним отдельным блоком. Положение блока определяется первой работой этой серии в быстром списке, а порядок внутри блока — расположением самих работ в списке.

## Редактирование биографии и раздела СМИ

В Pages CMS откройте «Текстовые страницы» и выберите:

- `CV` — биография, выставки и контакты;
- `СМИ` — публикации и ссылки на материалы.

После сохранения изменения автоматически публикуются тем же процессом, что и работы.

## Автоматическая публикация

Настройка находится в `.github/workflows/deploy-yandex.yml`, загрузка — в `scripts/deploy-yandex.sh`.

1. GitHub Actions получает изменения из ветки `main` и устанавливает зависимости через `npm ci`.
2. `npm run check` проверяет JavaScript и собирает сайт с адресом `https://omanovar.ru`.
3. Сначала загружаются изображения и стили, затем HTML-страницы. После успешной загрузки удаляются устаревшие файлы, включая удалённые в CMS работы.
4. Публикуется `deployment.json` с номером коммита, затем проверяются этот номер на публичном сайте и доступность страницы проектов.

При ошибке проверки или сборки публикация не начинается. Файлы получают `Cache-Control: no-cache`, чтобы при следующем открытии браузер проверял актуальность содержимого. Уже открытая страница обновляется обычной кнопкой перезагрузки.

Для публикации используется отдельный сервисный аккаунт `roman-site-github-deploy` с правами чтения списка и записи объектов только в бакете `omanovar.ru`. Его статический ключ хранится в секретах репозитория GitHub Actions: `YC_ACCESS_KEY_ID` и `YC_SECRET_ACCESS_KEY`. Значения ключей нельзя добавлять в файлы проекта. При замене ключа нужно обновить оба секрета в настройках репозитория.

Чтобы повторить публикацию без редактирования контента, откройте [процесс публикации](https://github.com/Nestert/Nestert.github.io/actions/workflows/deploy-yandex.yml), нажмите **Run workflow** и выберите ветку `main`.

## Резервная ручная публикация

В обычной работе эти действия не нужны. Не запускайте ручную загрузку одновременно с автоматической публикацией.

### Первоначальная настройка Yandex Cloud CLI

Установите официальный клиент:

```bash
curl -sSL https://storage.yandexcloud.net/yandexcloud-yc/install.sh | bash
exec zsh
```

Войдите под аккаунтом, которому принадлежит нужный бакет:

```bash
yc init --username=valbelsov@yandex.ru
```

Для этого проекта используются:

```bash
yc config set cloud-id b1girlkt5grj6up6to1g
yc config set folder-id b1g6kmlmgrl6d7sm8jrh
```

Проверка доступа:

```bash
yc storage bucket get omanovar.ru
```

Если ранее был создан профиль `valbelsov-deploy`, его можно активировать:

```bash
yc config profile activate valbelsov-deploy
```

Не публикуйте токены, статические ключи и содержимое каталога `~/.config/yandex-cloud` в GitHub.

### Получение контента и сборка

```bash
cd "/Users/valentinbelousov/new roman site"
git pull --ff-only origin main
npm install
SITE_URL=https://omanovar.ru npm run build
npm run lint
```

### Загрузка в Yandex Object Storage

```bash
yc storage s3 cp _site/ s3://omanovar.ru/ --recursive
```

Команда сохраняет структуру папок и заменяет изменившиеся файлы. Она не удаляет из бакета файлы, которых больше нет в `_site/`.

Если работа или изображение были удалены либо переименованы, нужна точная синхронизация. Не удаляйте весь бакет вручную: сначала сравните список локальных и удалённых объектов и удалите только устаревшие ключи. Безопаснее поручить такую синхронизацию Codex.

## Локальная разработка

Установка зависимостей:

```bash
npm install
```

Запуск локального сайта:

```bash
npm run dev
```

Сайт откроется по адресу <http://localhost:8080>.

Основные команды:

```bash
npm run dev      # локальный сервер и наблюдение за Sass
npm run lint     # проверка JavaScript
npm run build    # сборка в _site/ и подготовка Sites-версии в dist/
npm run check    # lint + build
npm test         # то же, что npm run check
```

## Структура проекта

```text
src/
├── _data/                  глобальные данные сайта и обложки серий
├── _includes/
│   ├── components/         шапка, подвал и другие компоненты
│   └── layouts/            шаблоны страниц
├── assets/
│   ├── images/             исходные изображения
│   ├── js/                 клиентский JavaScript
│   └── scss/               исходные стили
├── content/
│   ├── drawings/           графика
│   ├── paintings/          живопись
│   ├── projects/           проекты
│   └── objects/            инсталляции и объекты
├── admin/                  вход в Pages CMS и редактор миниатюр
├── cv.md                   страница «Биография»
└── press.md                страница «СМИ»
```

Сгенерированные файлы находятся в `_site/`. Не редактируйте их вручную: они пересоздаются при каждой сборке.

Стили нужно менять в `src/assets/scss/`. Файл `src/assets/css/main.css` создаётся Sass автоматически.

## Формат файла работы

Работы хранятся в `src/content/[category]/` в формате Markdown с YAML frontmatter:

```yaml
---
title: "Название работы"
year: 2026
dimensions: "51 × 49 см"
materials: "холст, масло"
series: "Праздник"
description: "Описание работы"
description_en: "English description"
image: "/assets/images/paintings/example.jpg"
gallery:
  - "/assets/images/paintings/example-detail-1.jpg"
  - "/assets/images/paintings/example-detail-2.jpg"
thumbnail: "/assets/images/paintings/example-thumb.jpg"
thumbnail_position:
  x: 35
  y: 20
  zoom: 140
order: 10
---

Необязательный дополнительный текст страницы.
```

Страницы создаются автоматически:

- `/projects/[slug]/`;
- `/projects/series/[slug]/` для автоматически собранных серий;
- `/paintings/[slug]/`;
- `/drawings/[slug]/`;
- `/objects/[slug]/`.

## Изображения

- Загружайте JPG, PNG или WebP.
- Не используйте очень длинные имена и специальные символы.
- Pages CMS автоматически приводит имена новых файлов к безопасному виду.
- Основное изображение выводится первым, а изображения из `gallery` — следом за ним в одной карусели.
- Порядок дополнительных фотографий задаётся их порядком в поле «Дополнительные изображения».
- Карусель управляется кнопками, клавишами со стрелками и свайпом на сенсорных экранах.
- Нажатие на изображение открывает полноэкранный просмотр исходного файла. Масштаб меняется кнопками, колесом мыши или жестом двумя пальцами; увеличенное изображение можно перетаскивать.
- Во время сборки создаются оптимизированные варианты изображений и `srcset`.
- Исходные файлы должны оставаться в `src/assets/images/`.

## Частые проблемы

### Pages CMS сохранил работу, но на сайте её нет

Убедитесь, что в Pages CMS выбрана ветка `main`. Откройте [GitHub Actions](https://github.com/Nestert/Nestert.github.io/actions/workflows/deploy-yandex.yml) и дождитесь завершения последней публикации. Если она завершилась с ошибкой, откройте красный запуск и проверьте шаг с ошибкой; после исправления повторите запуск через **Re-run jobs** или сохраните исправление в CMS.

### На сайте отображается старая версия

1. Убедитесь, что публикация завершилась без ошибок.
2. Обновите страницу через `Cmd + Shift + R`.
3. Проверьте нужную страницу напрямую.

### Команда `yc` не найдена

Установите Yandex Cloud CLI и перезапустите терминал командой `exec zsh`.

### Ошибка доступа к бакету

Проверьте аккаунт и профиль:

```bash
yc config profile list
yc config profile activate valbelsov-deploy
yc storage bucket get omanovar.ru
```

Для бакета нужен аккаунт `valbelsov@yandex.ru`. Аккаунт `omanovar@yandex.ru` относится к другому облаку и не имеет API-доступа к этому бакету.

### Удалённая работа всё ещё открывается по старой ссылке

Автоматическая публикация удаляет устаревшие файлы после загрузки новой сборки. Дождитесь зелёной отметки последнего запуска. Если использовалась резервная ручная загрузка через `yc storage s3 cp`, запустите автоматическую публикацию через **Run workflow**: ручная команда сама старые объекты не удаляет.

## Хостинг

Основная сборка предназначена для Yandex Object Storage. Бакет должен быть настроен как статический сайт со следующими страницами:

- главная страница: `index.html`;
- страница ошибки: `404.html`.

Для публичного сайта бакету требуется анонимный доступ на чтение. DNS, сертификат и переключение `omanovar.ru` на Yandex выполняются отдельно от загрузки файлов.

Sites остаётся тестовой площадкой. Публикация в Yandex не обновляет Sites автоматически, и наоборот.
